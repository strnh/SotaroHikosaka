# リファクタリング総括

> 本書は、年次セミナー申込システム（レガシー PHP）のリファクタリング業務を、
> 機微情報・固有名詞（組織名・個人名・サーバ情報等）を伏せて要約したものである。
> 機能仕様ではなく「何を負債と捉え、どう構造化しているか」を主眼とする。

## 概要

本システムは、年度ごとに申込フォーム一式を**年度別ディレクトリへ丸ごと複製**して
運用してきたレガシー PHP アプリケーションである。この運用の結果、申込処理を担う
中心ファイルは 1 本で 10 万字規模まで肥大し、同種ロジックが各年度に重複している。
この**巨大モノリスと重複**が負債の中心であり、リファクタリングの主対象となっている。

## リファクタリングの指針（長期目標）

1. **単一責任（SRP）**: 大きなスクリプトの分割、CSS/JS の分離、共通処理のクラス化、
   依存性注入、全システムで使う定数値の DB 化。
2. **負の遺産を継承しない**: 改修時はテンプレートエンジン・フレームワーク移行を前提に設計する。
3. **DB 運用体制の確立**: dump→migration→seed サイクル、冪等性の確保、IaC を意識した補助ツールの整備。
4. **フレームワークへの漸進的移行**: モデル化・テンプレート化を段階的に進める。
5. **要件定義の体系化（EARS）**: 自然言語要件を構造化する。
6. **ハードコードされた magic の外部化**: 設定値を DB / 環境ファイル / JSON へ追い出す。

## 現在の取り組み（実装の実態）

- **モノリスの分解**: 中心ファイルから責務を切り出し、DB アクセス・ビューモデル・
  入力検証・汎用ヘルパーを別ファイルへ分離している。1 ファイルに混在していた
  「取得・整形・検証・描画」を層として切り分ける方針。
- **安全な DB アクセス層**: 専用の DB クラスが用意した query / fetch 系ヘルパーを通じて
  アクセスし、生クエリの文字列連結やレガシー DB 拡張 API を置換。SQL インジェクション
  耐性を底上げし、レガシー API への逆戻りは静的チェックで退行防止している。
- **テンプレート化**: テンプレートレンダラを導入し、ビューを順次テンプレート形式へ
  移行。表示と処理の分離を進め、フレームワーク移行の前段としている。
- **セッション/セキュリティの抽出**: セッション管理、bot 対策、認証情報を専用モジュールへ分離。
- **設定の外部化**: 環境差分やマッピングを JSON 等へ追い出し、コード内の magic を削減。

## DB・インフラ運用の構造化

- migration / seed をディレクトリで管理し、dump→migration→seed のサイクルと
  **冪等性**を確保。通年で共有するデータは専用 DB に分離している。
- IaC を意識した補助スクリプト群を整備し、バックアップ・互換性チェック・
  プロビジョニング・同期を自動化。
- **破壊操作を構造的に排除**: 再帰削除を使わず、削除対象を manifest に列挙して
  1 件ずつ削除する仕組みを採用（本番での事故範囲を最小化）。

## 品質ゲート / ワークフロー

変更は「課題化 → 計画 → サンドボックスでの E2E → PR → クローズ」を標準フローとし、
本番反映前に必ず隔離環境で回帰確認を行う。E2E はブラウザ自動化を併用し、
CI とコードレビューで品質を担保。レビューでの頻出指摘は作業慣習として蓄積している。

## 今後

フレームワークへの段階移行、テンプレート分離の横展開、要件の EARS 化、
定数の DB 化を継続し、年度別複製に依存しない構造への転換を目指す。
